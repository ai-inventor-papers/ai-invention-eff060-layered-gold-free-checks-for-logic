Cross-Family Solver Consensus as a Gold-Free Faithfulness Metric for NL-to-FOL Translation

Anonymous · A Preliminary Study

Translating natural language into first-order logic is useful for formal verification and reasoning, but checking whether a formula actually captures a sentence's meaning normally requires a gold-standard reference. Gold references are expensive and often wrong: audits find roughly 40% of annotations in standard benchmarks contain errors. This paper tests a gold-free alternative. Several independent LLM families translate the same sentence, and an SMT solver checks whether the candidate formula agrees with the majority. On a development dataset of 2,686 labelled items, this consensus metric achieved stratified AUROC 0.741, beating the best cheap LLM judge by +0.099. Three peer families are enough for 97% of the signal. Confirmation on fresh data failed across every test cell, and the metric has a fundamental rename vulnerability: a 76.5% false-alarm rate when predicate names are changed.

Contributions

Head-to-head meta-evaluation

Cross-family solver consensus tested against API judges and a 28-feature baseline stack on NL-to-FOL faithfulness prediction. The consensus score outperforms the best cheap judge on development data and adds signal beyond all baselines combined.

Mechanistic decomposition

The consensus signal decomposes into endorsement (peers that agree with wrong formulas) and divergence (peers that disagree with correct ones). Errors scatter across equivalence classes while correct translations cluster, but this pattern degrades with sentence length.

Negative results on fresh data

The confirmation attempt produced no testable positive cell in the long-sentence stratum. The one testable stratum (short deterministic sentences) showed no advantage over a local judge. Every pre-registered criterion returned not testable or unfavourable.

Rename tradeoff documented

A 76.5% false-alarm rate under nonce predicate renames, which no variant eliminated without sacrificing error recall. The tradeoff is structural: any vocabulary bridge that lowers divergence also raises error endorsement.

Method

Consensus scoring

Given a sentence s and a candidate FOL formula c, the method [code] collects peer translations from k independent LLM families (Gemini, Claude, GPT, Llama, Qwen, Phi, Mistral), each using the same few-shot prompt but a different base model. The score is c_score_align = 1 − (1/k) ∑ equiv(c, pi), where equiv checks logical equivalence via the Z3 SMT solver after aligning predicate names. Higher scores mean greater divergence from the peer pool, and thus higher predicted error probability.

Predicate alignment

Independent translators choose different predicate names for the same concept (e.g. Runs(x) vs. IsRunner(x)). Before checking equivalence, predicates are aligned using a cost function that combines three signals:

  1. Structural cost. Polarity profile, argument-count match, and nesting depth.
  2. Text-anchor cost. Overlap between predicate-name words and source-sentence tokens, using Porter stemming and WordNet synonyms.
  3. Semantic signature. Truth-value profiles over random finite interpretations.

The cheapest bijections (within equal arity for predicates, separately for constants) are evaluated, and the pair is declared equivalent if any bijection yields a Z3-verified equivalence.

Variants

Four variants are evaluated alongside the primary c_score_align: c_exact (no alignment, exact-match equivalence only), c_nf (name-free alignment by structural and semantic signatures, ignoring text anchoring), g_score (graded, decomposes the candidate into claim units and scores the fraction unsupported by peers), and p_peer_text [code] (logistic fusion of consensus features with text-side features including bag-of-words coverage and Z3 structural match).

Evaluation framework

The development dataset contains 8,507 rows from 700 sentences drawn from the MALLS corpus and ProverQA. [code] Each sentence was translated by 9 LLM families. Labels come from a three-person expert panel (adjudicated as ERROR or CORRECT). The primary evaluation population (R_AB, both panellists agree) contains 2,686 items (1,822 ERROR / 864 CORRECT, 292 sentences) with complexity strata for long sentences, exception clauses, and short controls. The primary metric is stratified AUROC: items are paired only within the same source stratum, eliminating confounds from stratum-level base rates. Confidence intervals use sentence-cluster percentile bootstrap (B = 2,000).

On the 284-row subsample scored by the frontier judge (Gemini 3.1 Pro), c_score_align achieves 95.7% of the frontier judge's AUROC (ratio 0.957 [0.887, 1.034]) at 30× lower cost per item. Adding consensus to the frontier judge improves AUROC by +0.037 [+0.008, +0.066].

The consensus metric achieves Kendall τb = 0.692 [+0.513, +0.795] between system mean score and R_AB error rate across 13 system×variant configurations. On the vocabulary-exact subset (where candidate and gold share the same predicates), consensus still outperforms the judge (Δ = +0.306 [+0.232, +0.376]), ruling out the possibility that the advantage depends on vocabulary differences between good and bad candidates.

Mechanism

The consensus signal [code] decomposes into two components: endorsement e (fraction of ERROR items endorsed by the peer majority) and divergence d (fraction of CORRECT items that diverge from peers). The scatter index (ratio of pairwise disagreement among correct vs. error items per sentence) is 4.45 [3.57, 5.77]: error translations are far more diverse than correct ones.

The net consensus degradation from short to long sentences is Δ(e+d) = +0.356 [+0.198, +0.493], driven almost entirely by divergence (Δd = +0.608, Δe = −0.252). Correct translations of long sentences increasingly disagree with peers because independent models make different structural choices for complex quantifier scopes and exception clauses.

Three peer families suffice for 97% of the full-pool AUROC (k95 = 3), but the long-sentence tercile requires k95 = 5.

Confirmation attempt

The development results cannot confirm the metric's value because the development set was used to design the scoring pipeline. Two independent test sets were constructed.

E2-A [code] (550 fresh sentences) was budget-stopped before enough correct items accumulated. On the one testable stratum (DT, short sentences from ProverQA), consensus achieves stratified AUROC 0.916, tying the local judge (Δ = +0.003 [−0.042, +0.052]). On L25 sentences (≥25 words), c_score_align falls to 0.443 (below chance), with only 42 items.

R_COMP FREE [code] (long composed sentences with independent vocabulary [code]) required a gloss gate for confirmatory labels. This gate failed twice (balanced accuracy 0.776 and 0.561, below the 0.90 threshold), producing zero confirmed CORRECT rows. Under provisional non-confirmatory labels, c_score_align achieves within-template AUROC 0.801 [0.770, 0.834] vs. the disguised judge's 0.584 [0.550, 0.618] (Δ = 0.217 [0.175, 0.260]).

The rename tradeoff

The predicate aligner [code] introduces a fundamental false-alarm vulnerability. When correct formulas are copied with meaning-preserving predicate renames, the consensus score should not change. In practice, the false-alarm rate is high.

The name-free variant c_nf eliminates rename sensitivity (flip = 0) but at the cost of blindness to meaning-rename errors (within-base AUROC 0.499, chance level) and lower overall discrimination (strat AUROC 0.686 vs. 0.741). Every vocabulary bridge that lowers divergence d also raises endorsement e: the aligner lowers d from 0.583 to 0.328 but raises meaning-rename endorsement from 0.104 to 0.624.

Dead ends

Several alternatives were investigated and abandoned: a fused structural-feature filter (false-alarm gate failure); name-free consensus c_nf (rename-invariant but blind to meaning-rename errors); a decomposed solver-based semantic reader (balanced accuracy 0.476); LLM adjudication of disputed items (balanced accuracy 0.662 on expert-labelled items); and candidate-signature consensus [code], which scored candidates by cueing peers with the candidate's own predicate symbols (provisional negative: error endorsement rose to 0.459 because peers were anchored into reproducing the candidate's errors).

Limitations

  1. Development data only. Every positive result reported above is on data used to design the metric. The confirmation attempt produced no testable positive cell.
  2. Rename vulnerability. A 76.5% false-alarm rate on nonce renames means the metric will systematically penalise any translation that uses non-standard predicate names, even if semantically correct.
  3. Length degradation. Consensus discrimination degrades with sentence length (NET +0.356), driven by correct-translation divergence. The metric is weakest on the longest, most complex sentences, precisely the cases where gold-free evaluation is most needed.
  4. Label dependence. All development results depend on a three-person panel whose agreement is imperfect. The metric's advantage could partly reflect alignment with panel biases rather than with ground-truth faithfulness.
  5. Cost. While cheaper than a frontier judge, the consensus metric requires generating k peer translations per sentence, costing $0.95 per 1,000 sentences at k = 3.
  6. Domain. All results are on English-to-FOL from MALLS and ProverQA sources. Generalisation to other logic formalisms, languages, or sentence distributions is untested.
